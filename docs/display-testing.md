# Display testing

Run `npm run test:display` separately from `npm test`. It starts Vite on an ephemeral loopback port and opens a fresh retained Chrome profile; installed Chrome, Node and the project dependencies are required. Set `FOLIO_CHROME_CHANNEL` to another installed Playwright Chromium channel if needed. The runner imports generated PDFs through the reader, scans Contents, then examines Book page-flip and Scroll at desktop and narrow sizes. Its intended prose, heading roles, and Contents titles, source pages and PDF baselines are authored with the fixtures, independently of the reader's extraction. A fallback `Entire book` Contents entry and its generated introduction are expected for the prose-only fixture. Other generated introductions are compared against the fixture expectations.

The fixtures cover clean prose and genuine chapters, repeated chapter headers with changing folios, alternating split headers, repeated author headers, a genuine top-edge chapter, and numbers in ordinary prose. Two adjacent pages end and begin with the clauses of a continuous sentence. The runner collects all fitted leaves for selected source pages, checks ordered text and headings, detects unexpected generated introductions and mismatched Contents, and checks text ranges for clipping or hidden styling. Scroll text is brought into the viewport line by line. This is a bounded regression suite, not a general PDF fidelity or performance audit. Expected panels are semantic references, not pixel-perfect renderings of the original PDF. Screenshots are evidence, not automatically accepted image baselines.

Reports, screenshots, the isolated profile and Vite cache are retained in the ignored `output/playwright/display-suite/run-*` directory. Open `report.html` for expected versus observed text and screenshots, or inspect `report.json` for details. The status and planned/executed counts distinguish completed results from interrupted or incomplete runs. Product assertion failures and harness errors are listed separately, and either produces a nonzero exit. A failing run is not a snapshot approval.

Run `npm run test:display:oracle` to exercise the comparator on correct observations and injected missing, duplicate and inserted text, wrong headings and anchors, and hidden/clipped text. It does not replace the browser run. The default suite uses no third-party PDFs and does not assert the particular Frankenstein edition; [the running-header research report](running-header-detection-research.md) documents that edition's physical pages 81–82.

Run `npm run test:display:browser-oracle` to import the clean fixture and deliberately hide and clip rendered text, then confirm the same collector rejects both mutations. The full suite also performs these checks. Scroll checks whether each line can be brought into view; screenshots capture the initial view, not every traversed line.

`npm run test:display:extended` runs the display suite, the existing browser fidelity checks for emphasis, real Hamlet pages 10/20/50 and OCR/encoding mismatch, and the scanned/mixed-page fallback check in a browser against current source. Each retains its own report or console result. The scan check requires the three generated scan fixture PDFs in `output/playwright`; if missing, the extended command reports incomplete. `node tests/create-fixtures.mjs` generates them but also overwrites other fixture files in that directory, so inspect existing files first and never pass `--sample` for this purpose.

The display fixtures now also include two-column prose, a small table and a rotated page. The table check requires each label and value to remain in the same text block and on one rendered line; it does not guarantee full visual table reconstruction. Set `FOLIO_FRANKENSTEIN_PDF` to the supplied `frank-a5.pdf` before running the display or extended command to check its physical pages 81–82. The runner verifies the documented edition's SHA-256, checks selected passage text, visibility and absence of the repeated Chapter VI heading in both modes and viewports. This real-document check is partial: it does not assert the full text, Contents or image fidelity. Without the variable, it is omitted. Hamlet's fidelity checks compare with the reader's extracted model, not an independent transcription. Synthetic OCR, scan and image checks do not replace real scanned or image-rich PDFs. Set `FOLIO_DISPLAY_CASE` to a fixture name to run just that fixture during diagnosis; this focused run only exercises the browser checker mutations when `clean` is selected.

The reader recognizes a conservative pattern of at least three adjacent rows with aligned short text labels and numeric cells. It retains each recognized row as a line of text; it does not reconstruct table columns, borders, headers, or arbitrary table layouts. Other tables may still require Original PDF view.
