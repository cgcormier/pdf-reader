# Display testing

Run `npm run test:display` separately from `npm test`. It starts Vite on an ephemeral loopback port and opens a fresh retained Chrome profile; installed Chrome, Node and the project dependencies are required. Set `FOLIO_CHROME_CHANNEL` to another installed Playwright Chromium channel if needed. The runner imports generated PDFs through the reader, scans Contents, then examines Book page-flip and Scroll at desktop and narrow sizes. Its intended prose, heading roles, and Contents titles, source pages and PDF baselines are authored with the fixtures, independently of the reader's extraction. A fallback `Entire book` Contents entry and its generated introduction are expected for the prose-only fixture. Other generated introductions are compared against the fixture expectations.

The fixtures cover clean prose and genuine chapters, repeated chapter headers with changing folios, alternating split headers, repeated author headers, a genuine top-edge chapter, and numbers in ordinary prose. Two adjacent pages end and begin with the clauses of a continuous sentence. The runner collects all fitted leaves for selected source pages, checks ordered text and headings, detects unexpected generated introductions and mismatched Contents, and checks text ranges for clipping or hidden styling. Scroll text is brought into the viewport line by line. This is a bounded regression suite, not a general PDF fidelity or performance audit. Expected panels are semantic references, not pixel-perfect renderings of the original PDF. Screenshots are evidence, not automatically accepted image baselines.

Reports, screenshots, the isolated profile and Vite cache are retained in the ignored `output/playwright/display-suite/run-*` directory. Open `report.html` for expected versus observed text and screenshots, or inspect `report.json` for details. The status and planned/executed counts distinguish completed results from interrupted or incomplete runs. Product assertion failures and harness errors are listed separately, and either produces a nonzero exit. The current fixture matrix passes with the shared running-header detector. A failing run is not a snapshot approval.

Run `npm run test:display:oracle` to exercise the comparator on correct observations and injected missing, duplicate and inserted text, wrong headings and anchors, and hidden/clipped text. It does not replace the browser run. The default suite uses no third-party PDFs and does not assert the particular Frankenstein edition; [the research report on its published branch](https://github.com/cgcormier/pdf-reader/blob/codex/running-header-research-2026-11-11/docs/running-header-detection-research.md) documents that edition's physical pages 81–82.

Run `npm run test:display:browser-oracle` to import the clean fixture and deliberately hide and clip rendered text, then confirm the same collector rejects both mutations. The full suite also performs these checks. Scroll checks whether each line can be brought into view; screenshots capture the initial view, not every traversed line.
